# Стенд ESP32 — настоящий датчик для демо

Плата отправляет «сырые» показания каждые 2 с на `POST /api/ingest`. Пороги и логика — на сервере
(`backend/app/quality.py`): базовый уровень подстраивается под конкретный датчик, после включения/восстановления связи
120 с идёт прогрев (тревога считается неподтверждённой), невозможные значения отбрасываются.

## Что купить (ориентировочно, цены уточните в магазине)
| Деталь | Зачем |
|---|---|
| ESP32 DevKit (ESP-WROOM-32) | Wi-Fi плата |
| Модуль MQ-2 | дым / горючие газы (аналоговый выход AO) |
| DS18B20 (лучше в гильзе) + резистор 4,7 кОм | температура |
| Делитель 10 кОм + 20 кОм | MQ-2 питается от 5 В, а вход ESP32 — до 3,3 В |
| Датчик пламени KY-026 (необязательно) | ИК-пламя, цифровой выход |
| Макетная плата, провода, USB-кабель | |

## Подключение
```
MQ-2  VCC → 5V (VIN)   GND → GND   AO → [10k] → GPIO34 → [20k] → GND
DS18B20  VDD → 3V3   GND → GND   DQ → GPIO4  (+ 4,7 кОм между DQ и 3V3)
KY-026  VCC → 3V3   GND → GND   DO → GPIO27   (HAS_FLAME = true в скетче)
```

## Запуск
1. В приложении: «Объекты» → нужный объект → инструмент «Датчик» → кликните на плане → тип «Мультисенсор», ID `ESP-01`.
2. Arduino IDE → плата «ESP32 Dev Module», библиотеки OneWire и DallasTemperature.
3. В `tutinguard_esp32.ino` впишите Wi-Fi, адрес компьютера с сервером (`ipconfig`/`ifconfig`), `INGEST_TOKEN` из `.env`.
4. Если сервер запущен через Docker, откройте порт в локальную сеть: в `.env` `BACKEND_BIND=0.0.0.0`.
5. Залейте скетч, откройте монитор порта (115200): должно быть `HTTP 200`.
6. Подождите 2 минуты (прогрев MQ-2 и сервера). Поднесите **тлеющую ароматическую палочку** (не открытый огонь) —
   «Внимание», через пару секунд «Тревога»; второй датчик в той же зоне или повторный сигнал подтверждают пожар.

## Без железа
`python hardware/esp32/fake_esp32.py --server http://localhost:8000` — эмулятор: `s` дым, `h` нагрев, `x` невозможное значение.
